# 常见问题

先打开 **输出 → QEMU Assembly**，再执行 **QEMU Assembly: 检查环境**。若需要排查实际调试能力，执行 **QEMU Assembly: 打开依赖与能力报告**；它提供只读 JSON，可复制或另存。

基础检查不构建用户工程、不连接客体，也不会自动安装工具。工具存在、版本可识别、协议可用、完整功能通过是不同层次；报告中的 `unknown` 代表尚未验证，不能当作成功或失败。

## 工具找不到或路径不对

| 现象 | 检查方法 |
| --- | --- |
| 终端能执行，插件提示找不到 | 确认终端和扩展位于同一个宿主；VS Code 启动后 PATH 发生变化时重新打开窗口 |
| 工具位于含空格路径 | 设置中只填写完整可执行路径，不加外层引号，不把参数写入路径 |
| 相对路径与预期不同 | VS Code 工具设置相对所选工作区；项目内 `build.command`、`debug.gdbPath` 相对项目根 |
| 本地已安装，WSL/容器/SSH 窗口仍报错 | 在远程扩展宿主安装并配置；本机 Windows `.exe` 路径不能直接作为 Linux 工具路径 |
| NASM 项目要求安装 GDB | 核对是否误配了 `debug.elf`；普通 NASM 调试不依赖 GDB |

不要在路径里使用 `~`、环境变量、`${workspaceFolder}` 或 Windows 的 `C:tool.exe`。完整解析规则见[配置参考](CONFIGURATION.md#vs-code-设置)。

## 构建失败，或者旧镜像消失

构建开始前会使旧镜像失效，失败、超时或取消后不会继续运行旧产物。这是预期行为；插件不删除项目自己的 ELF 或其他构建产物。

- NASM 语法错误看“问题”面板；点击条目跳到实际文件和行。
- 单扇区镜像必须为 512 字节，末尾 `55 aa`；多阶段项目和外部镜像有独立大小、对齐与布局约束，见[配置参考](CONFIGURATION.md)。
- 外部构建默认超时 120 秒，可用 `build.timeout` 调整。`build.command` 不经 shell；`make debug` 应写为 `command: "make"` 与 `args: ["debug"]`。
- Windows `.cmd/.bat` 需要显式解释器，不能当作普通可执行文件启动。
- 若输出提示 Workspace Trust，先确认项目可信，再启用工作区信任。

## 断点为空心或不命中

**NASM：**在可执行指令行设置断点，标签、数据、注释行不接受。检查 `BITS`、`ORG` 和阶段 `loadAddress` 是否一致；宏、include、条件预处理等不提供可靠 listing 映射。客体必须实际加载并执行该地址，构建配置不会代替加载器读盘。

**C：**确认配置了匹配当前镜像的 ELF32/DWARF 文件，且客体按 ELF 链接地址运行。源码行断点可能由 GDB 移到相邻可执行行；优化后的行和变量可能不存在。不同目录构建时使用 `debug.sourceMap`。较旧 GDB 可能无法读取较新的 DWARF，可让项目生成该 GDB 支持的调试信息；已验组合见[兼容性](COMPATIBILITY.md)。

修改源码后重启调试以重新构建。条件、命中次数和日志断点尚未提供；未知源码可用反汇编和地址断点观察。

## 调用栈不完整，或变量为空

NASM 只能验证标准 BP/EBP 的 near CALL 调用链。手写栈、无帧指针、far CALL 或混合宽度不保证展开；原始栈仍可查看。C 栈和变量由 GDB/DWARF 提供，受优化与实际展开信息影响。

继续执行后旧帧和变量句柄失效；再次暂停再展开当前帧。历史调用者没有寄存器快照，寄存器和 CPU 模式请查看当前帧。监视表达式只读，函数调用、赋值、递增和类型转换会被拒绝。

## F10 或反汇编提示解码器不可用

解码器的 JS/WASM 随 VSIX 分发，并在首次需要时加载。源码调试之外，NASM 无映射代码的 F10 也需要解码器；可先用 F11 指令单步继续排查。

如果使用自行打包的 VSIX，按[开发指南](DEVELOPMENT.md#打包与独立安装验证)重新打包，确保保留生产依赖；不要用 `--no-dependencies` 排除解码器。该错误不要求终端用户安装 Node/npm。

## 数据断点没有在相同值写入时暂停

C/GDB 写断点使用 GDB 的**值变化**语义，相同值写入不会暂停；NASM/RSP 写断点按写访问暂停。读取和读写断点按对应访问暂停。数据断点绑定具体地址，局部变量离开作用域后不会自动转移到新地址。

访问完成后才产生停机，PC 可能已指向下一条指令。完整差异见[数据断点](DEBUGGING.md#数据断点)。

## 显示器没有画面

1. 检查 `qemuAsm.displayMode` 是否为 `auto`，以及 QEMU 是否仍在运行；手动执行 **QEMU Assembly: 显示模拟显示器**。
2. 查看输出日志和面板错误，区分资源分配、QMP 连接、截图文件读取失败。
3. QMP 截图要求 QEMU 与扩展宿主共享文件命名空间；仅端口可连接不足以支持跨宿主画面。
4. 若当前 QEMU 不接受显示相关启动参数，设 `qemuAsm.displayMode: "off"` 后重启，再验证基础运行和调试。

CPU 暂停时仍可截图；关闭面板不会停止 QEMU。键盘默认不转发，需先开启输入并点击客体屏幕获得焦点。鼠标、音频和输入法组合文字暂不支持。

## 物理内存或页表不可用

物理读取要求目标支持 `qqemu.PhyMemMode` 扩展；缺少时不能用虚拟读取冒充物理结果。页表查看器支持普通 32 位非 PAE 分页和 4 KiB / PSE 4 MiB 页，不支持 PAE、64 位或 PSE-36 高物理地址。

虚拟地址缺页、段越界、机器模式不支持，均可能正确地返回错误。若 CPU 正在运行，先暂停；旧快照会明确标记。

## 提交问题时附哪些信息

- 插件版本、VS Code 版本、宿主系统与架构，以及是否使用 WSL/容器/SSH。
- 依赖报告中的实际工具路径、版本、失败能力与原因；分享前可隐去私人目录。
- 最小 `qemu-asm.json`、构建方式、复现步骤，以及输出日志的相关错误。
- 预期结果、实际结果、是否能用最小引导项目复现。

提交到 [GitHub Issues](https://github.com/nothingzhl/vscode-qemu-asm/issues)。当前平台与工具组合请以[兼容性记录](COMPATIBILITY.md)为准。
