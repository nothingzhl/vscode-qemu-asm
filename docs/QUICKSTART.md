# 第一次运行与调试

目标：从安装好的插件和工具开始，在 VS Code 中停住一个引导程序、查看寄存器，并看到 QEMU 的真实画面。安装工具的时间不计入五分钟。

## 1. 准备环境

- VS Code 1.96 或更新版本，已通过“从 VSIX 安装”安装本插件。
- 当前扩展宿主能执行 NASM 和 `qemu-system-i386`。本流程不需要 GDB。
- 一个本地空文件夹。使用 WSL、容器或 SSH 时，文件夹和工具应位于同一扩展宿主。

在 VS Code 打开该文件夹并启用 Workspace Trust。打开命令面板：Windows/Linux 使用 `Ctrl+Shift+P`，macOS 使用 `Cmd+Shift+P`。

执行 **QEMU Assembly: 检查环境**。如果工具不在 PATH，在设置中填写 `qemuAsm.nasmPath`、`qemuAsm.qemuPath` 的实际路径，然后重新检查。路径有空格时无需额外包裹引号。

**应看到：**报告识别 NASM、QEMU 的实际路径和版本。基础检查通过仅说明工具可执行，后面的运行才验证引导和调试协议。

## 2. 创建最小项目

执行 **QEMU Assembly: 创建引导项目**，选择刚才的目录。插件创建：

```text
你的项目/
├── boot.asm
└── qemu-asm.json
```

插件会记录当前工作区的项目位置；同名文件已存在时拒绝覆盖。已有项目请直接添加[项目配置](CONFIGURATION.md)，无需生成模板。

## 3. 构建并看到画面

执行 **QEMU Assembly: 构建并运行**，打开 **输出 → QEMU Assembly**。

**应看到：**右侧出现“QEMU 模拟显示器”，日志和客体屏幕出现 `QEMU_ASM_BOOT_OK`。执行 **QEMU Assembly: 停止**，结束本次运行。停止后显示器保留最后一帧。

未看到标记时先核对输出日志；构建错误可在“问题”面板点击跳到源码。每次运行都会重新构建，失败不会使用旧镜像。

## 4. 在第一条指令暂停

打开 `boot.asm`，执行 **QEMU Assembly: 开始引导调试**。默认停在 BIOS 已装入引导扇区后的 `0x7c00`。

**应看到：**源码当前指令高亮，调试工具栏出现，左侧“运行和调试”显示调用堆栈和变量。

| 操作 | 快捷键 | 观察什么 |
| --- | --- | --- |
| 单步进入 | F11 | 当前指令、寄存器和栈如何变化 |
| 设置/取消源码断点 | F9 | 在可执行指令行设置；标签和数据行不接受断点 |
| 继续到断点 | F5 | 客体继续运行，命中后再次暂停 |
| 单步跳过 | F10 | CALL / INT 执行到下一条指令 |
| 跳出函数 | Shift+F11 | 有可验证 BP/EBP 调用者时返回上一层 |

部分系统需要同时按 Fn。`.asm` 被其他扩展接管时，在编辑器右下角选择 **NASM（操作系统学习）** 语言模式。

## 5. 看寄存器、栈与内存

暂停时展开 **变量 → 寄存器**，查看 AX/EAX、SP/ESP、BP/EBP、段寄存器和 EFLAGS；在“监视”中输入 `AX`、`CS:IP` 或 `SS:SP`。

执行 **QEMU Assembly: 查看内存与描述符表**，打开底部“QEMU 调试观察器”。内存页输入地址，或选择跟随栈指针；CPU 运行时保留并标注上次快照，先暂停再读取新状态。

完成后点击调试工具栏停止，或执行 **QEMU Assembly: 停止**。插件只清理自己启动的进程。
