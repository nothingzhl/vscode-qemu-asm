# 调试指南

还未完成第一次调试时，先读[快速开始](QUICKSTART.md)。本页说明已有项目如何调试，以及看到的状态具体代表什么。

## 选择调试环境

项目定义了多套机器配置后，先执行 **QEMU Assembly: 选择启动方案**，再开始运行或调试。方案可设置内存、CPU 型号和显示器开关；用 **QEMU Assembly: 配置启动方案** 编辑配置和查看字段提示，完整示例见[启动方案](CONFIGURATION.md#启动方案)。

切换不会改变正在运行的 QEMU，下次启动或重启才生效。`launch.json` 显式填写的 `machineProfile` 优先于手选和项目默认方案；重启保持该名称并重读其配置值。没有显式指定时，重启读取当前手选或默认方案。每次重启都会重新构建、分配资源并清除旧快照与句柄。

启动日志和依赖与能力报告会列出方案、来源及生效的机器配置。CPU 型号不可用或方案不存在时先修正配置；插件不会用其他方案悄悄启动。不同 CPU 型号的指令与分页能力可能不同，仍需让客体代码与所选机器匹配。

## NASM 源码与寄存器

打开 `.asm` 文件，在可执行指令行左侧设置断点，再执行 **QEMU Assembly: 开始引导调试**。若语言模式被其他扩展接管，在编辑器右下角选择 **NASM（操作系统学习）**。

| 操作 | 快捷键 |
| --- | --- |
| 继续 / 暂停 | F5 / 调试工具栏暂停 |
| 单步进入 / 跳过 / 跳出 | F11 / F10 / Shift+F11 |
| 设置、取消源码断点 | F9 |
| 重启 / 停止 | 调试工具栏；也可执行插件停止命令 |

NASM 单步按实际指令执行。F10 遇到 CALL / INT 时运行到下一条指令，期间用户断点仍然生效；跳出要求存在可验证的调用者。基础 NASM 调试直接连接 QEMU RSP，无需 GDB。

暂停时可查看：

- **寄存器**：AX/EAX、SP/ESP、BP/EBP、段寄存器、EFLAGS 和展开后的标志位，以及 CR0/2/3/4、EFER、段缓存。
- **CPU 模式与地址**：当前实/保护模式、代码和栈指针位宽、线性地址与 CR0.PE/PG。地址按 CPU 实际段缓存计算，保护模式 EIP/ESP 不会截断到 16 位。
- **调用堆栈**：当前指令与可验证的 BP/EBP 调用链。无法还原调用者时仍可查看原始栈。
- **监视与调试控制台**：`AX`、`$eax`、`CS:IP`、`CS:EIP`、`SS:SP`、`SS:ESP`、`mode`、`[0x7bfa]`、`dword[0x8fff0]`。内存表达式使用当前虚拟线性地址空间。

历史调用者没有寄存器快照，寄存器和原始栈应选择当前帧查看。修改源码后重启调试，以重新构建镜像和映射。

## 二阶段与保护模式

在空目录执行 **QEMU Assembly: 创建二阶段保护模式项目**，得到加载到 `0x7c00` 的引导程序，以及加载到 `0x8000` 的 `stage2.asm`。

1. 在 `stage2.asm` 的 `mov cr0, eax` 附近设置断点，开始调试并继续到断点。
2. 用 F11 观察 `CR0.PE` 置位。此刻 CS 默认指令宽度仍是 16 位；执行 `jmp 0x08:protected_entry` 后才进入 32 位代码。
3. 继续经过 `mov ss, ax`、`mov esp, 0x90000`，观察段寄存器与栈变化。
4. 在 `learning_breakpoint` 后的 `nop` 暂停，查看 EAX/EBX 的 `0x11223344`、EBP 链、参数与返回地址。屏幕和串口应显示 `PROTECTED_MODE_OK`。

该模板仅用于环境检查和状态观察：最小平坦 GDT、IF=0、关闭分页，IDT 仅有向量 3 的门与处理器，不是完整内核。已有工程不会被自动更新；体验模板时使用空目录。

## 调试 C 内核

在 `qemu-asm.json` 配置项目自己的构建命令及 `debug.elf`，见[完整配置示例](CONFIGURATION.md#外部构建与-c-源码调试)。构建应生成可引导 raw 软盘和带 DWARF 的 i386 ELF32 `ET_EXEC`。项目加载器必须把代码装入 ELF 链接地址；插件不代替加载器，也不执行 GDB `load`。

调试构建可使用 `-m32 -ffreestanding -fno-pie -fno-pic -O0 -g -fno-omit-frame-pointer`。实际 DWARF 版本必须能被所选 GDB 解释；工具与版本组合见[兼容性](COMPATIBILITY.md)。

打开 `.c` 文件设置行断点，执行同一开始调试命令。配置 `debug.elf` 后自动使用 GDB 后端：

- 默认停在 `debug.entry` 或 ELF 入口。F10/F11/Shift+F11 按 **C 源码**跳过、进入和跳出；原生反汇编也可按指令单步。
- 行断点由 DWARF 绑定，可能移到相邻的可执行行，界面显示实际绑定行。
- 选择调用栈帧后查看该帧的参数和局部变量，可展开结构体、数组和指针；寄存器、原始栈与 CPU 模式仅属于当前帧。
- 监视、悬停支持 `sample.left`、`values[1]`、`cursor->right`、`*cursor`、`cursor[2]`、`$eax` 与基本算术。表达式只读，拒绝赋值、自增、自减、函数调用、逗号表达式和类型转换。
- 优化可能移除变量或改变源码位置；继续、再次暂停或重启后旧变量句柄失效，不会显示成新帧的数据。

同一会话仍可使用内存、反汇编、描述符、页表和显示器。源文件目录不同可配置 `debug.sourceMap`；数据断点绑定实际地址，局部变量离开作用域后不会自动追踪新栈地址。

## 内存、GDT、IDT 与 IVT

暂停后执行 **QEMU Assembly: 查看内存与描述符表**，打开底部调试观察器。

| 页签 | 操作与结果 |
| --- | --- |
| 内存 | 输入十六进制或十进制地址，每页查看 256 字节、ASCII 与变化高亮；虚拟模式可跟随 SS:SP/ESP 或 SS:BP/EBP |
| GDT | 查看 GDTR、段类型、base/limit、P/DPL、位宽与 G；标记当前选择子，段缓存与表项不同时提示 |
| IDT | 实模式查看 IVT 的段、偏移和地址；保护模式解码 16/32 位中断门、陷阱门与任务门 |

表格分页读取并受表界限约束；单次最多读取 128 项。视图只读，CPU 运行时保留标注的上次快照；再次暂停后刷新。隐藏视图不主动读取，重启、终止或切换会话会清空旧数据和变化基线。

## 反汇编与地址断点

暂停后执行 **QEMU Assembly: 查看反汇编**。页签默认跟随当前 PC，显示地址、机器码和 NASM 风格指令；可跳到线性地址、翻页，点击行首圆点添加地址断点。也支持 VS Code 原生反汇编和指令断点。

解码使用当前 CS 基址、界限及 16/32 位模式。手动地址应指向指令起点；无法确定的前驱边界、无效编码或不可读字节会标记出来。解码器随 VSIX 分发，首次使用时加载；NASM 无源码映射的 F10 同样需要解码器，故障时可先使用 F11。

## 数据断点

执行 **QEMU Assembly: 查看数据断点**，设置线性地址、1/2/4 字节范围以及写入、读取或读写类型，再继续执行。支持 VS Code 原生数据断点；最多配置 16 个不同数据断点，实际资源由后端决定。

| 后端 | 写入断点 | 读取 / 读写断点 |
| --- | --- | --- |
| NASM / QEMU RSP | 按写访问暂停，即使写入值相同 | 按对应访问暂停 |
| C / GDB | 按 GDB 的值变化语义，写入相同值不暂停 | 按对应访问暂停 |

访问指令已完成后才暂停，PC 通常指向下一条指令。读写命中不区分本次是读还是写；相同起点/类型但长度不同可能报告多个候选。面板和原生断点分别管理，删除面板项不会删除原生配置；同会话重启保留配置并清空旧命中，结束时释放绑定。

## 页表与虚拟/物理地址

暂停后执行 **QEMU Assembly: 查看分页与地址转换**。输入虚拟线性地址，查看 CR3 → PDE → PTE → 物理地址，以及原始表项、4 KiB / 4 MiB 页大小、P/RW/US 和 CR0.WP 的影响。

页目录和页表从物理内存读取，无需客体进行恒等映射。内存页可切换虚拟/物理地址空间；物理读取要求目标支持 `qqemu.PhyMemMode` 扩展，缺少时明确提示。缺页、无效表项或不支持状态不会生成猜测的物理地址。

当前支持普通 32 位非 PAE 分页。页表展示为内存快照，不读取 TLB；页级权限解释不代替段权限、CPL 等保护检查。NASM 源码映射还要求原加载地址的恒等映射成立；重定位或别名代码使用反汇编和地址断点。

## 右侧模拟显示器

运行或调试时自动在源码右侧显示真实 QEMU VGA 画面；手动入口为 **QEMU Assembly: 显示模拟显示器**。

- 可选择“适应”或“1:1”，手动刷新；CPU 暂停时仍能查看画面。
- 关闭面板不会停止 QEMU；重开恢复画面，停止后保留最后一帧。
- 键盘输入默认关闭。开启后点击屏幕获得焦点，才转发普通键、方向键、功能键和常见组合键；支持发送 Ctrl+Alt+Del。
- 不转发鼠标、音频或输入法组合文字，刷新机制面向引导程序和实验观察。

显示器通过 QMP 读取截图和发送受限键码，截图要求 QEMU 与扩展宿主共享文件命名空间。使用启动方案的 `display: false`，或在方案未覆盖时设置 `qemuAsm.displayMode: "off"`，可关闭显示资源；连接、截图故障会显示原因，详见[排错](TROUBLESHOOTING.md#显示器没有画面)。

## 支持范围

- **NASM 映射**：`-f bin` 平坦二进制，每文件显式 `BITS 16/32`、唯一 `ORG` 与配置加载地址一致。宏、include、incbin、section 和条件预处理不提供可靠源码映射。标签、数据和注释不接受源码断点。
- **CPU 与地址**：单 CPU，标准实模式、PE 切换后远跳转前的 16 位状态、32 位保护模式，以及非 PAE 的 4 KiB / PSE 4 MiB 页；物理地址限 32 位。PAE、PSE-36 高物理地址、虚拟 8086、SMM、unreal mode 和 64 位不支持。
- **调用者**：NASM 使用标准 near CALL 的 BP/EBP 链；任意手写栈、无帧指针、混合宽度与 far CALL 不保证还原。C 使用 GDB/DWARF 展开信息。
- **只读观察**：寄存器、内存、变量与描述符只读。条件、命中次数和日志断点、LDT 表、完整中断调试、远程 attach、C++ 与 SMP 尚未提供。
- **状态与安全**：读机器状态要求可信工作区和暂停的会话；旧快照会标记。缺失段缓存等影响地址正确性的状态时明确失败，不猜测平坦段。

工具能力、平台状态和具体版本见[兼容性](COMPATIBILITY.md)，各阶段原始证据见[历史验证索引](README.md#历史验证记录)。
